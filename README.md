# Newton

## Что такое Newton

Прошивка домашнего контроллера на ESP32 (плата Kincony KC868-A2): освещение, тёплый пол, климат и присутствие. Устройство общается с модулями WirenBoard по RS-485 (Modbus RTU), публикует состояние в MQTT и автоматически регистрирует сущности в Home Assistant. Настройка — через локальный веб-интерфейс.

Версия прошивки: **0.1.0**. Проект рассчитан на домашнюю эксплуатацию в доверенной сети: у веб-интерфейса нет авторизации и HTTPS.

## Возможности

- **Автоматическое освещение** по присутствию и освещённости: свет включается, когда человек обнаружен, а освещённость ниже ~150 лк держится около минуты (120 опросов по 0,5 с). Когда человек уходит, свет выключается.
- **Ручное переопределение**: команда с физической кнопки, Home Assistant или MQTT переводит свет в ручной режим. Если свет включили вручную, автоматика возвращается через 5 минут; если выключили — через 10 минут после последнего обнаружения человека.
- **Ночной режим**: когда автоматика включает свет, основной свет горит красным на минимальной яркости (~2 %, 2700 K); длинное нажатие кнопки яркости продолжает работать.
- **Основной свет WB-LED1** (CCTWW): плавная яркость и температура 2700–6000 K. Физическая кнопка: короткое нажатие — включить/выключить, длинное — яркость.
- **Подсветка WB-LED2** (RGBW): цвет и яркость; физически отсутствует и временно исключена из ночного режима.
- **Тёплый пол**: включение/выключение с гистерезисом ±1 °C, уставка 16–40 °C, опрос каждые 2 секунды. При отказе датчика (более 20 ошибок подряд) реле принудительно выключается, а healthcheck сообщает об ошибке.
- **Климат WB-MSW**: температура, влажность, качество воздуха (с фильтром Калмана), CO₂ и освещённость; опрос каждые 10 секунд, публикация с retain и heartbeat раз в 60 секунд.
- **Датчик присутствия MTD262MB**: опрос каждую секунду, публикация с retain и heartbeat раз в 60 секунд.

## Оборудование

| Устройство | Адрес по умолчанию | Назначение |
|---|---:|---|
| Kincony KC868-A2 | — | Контроллер ESP32, RS-485, реле |
| WirenBoard WB-MSW | 1 | Температура, влажность, качество воздуха, CO₂, освещённость |
| WirenBoard WB-LED1 | 3 | Основной CCT-свет |
| WirenBoard WB-LED2 | 4 | RGBW-подсветка |
| WirenBoard WB-M1W2 | 5 | Датчик температуры тёплого пола (канал 1-Wire 1) |
| MTD262MB | 6 | Датчик присутствия |

Без RS-485-устройств прошивка запустится, но данных от света, климата, тёплого пола и присутствия не будет. Адреса и скорость Modbus можно изменить в веб-интерфейсе.

## Подключение

| Что | Контакт / параметр |
|---|---|
| Шина RS-485 | Клеммы A/B платы; UART: RX GPIO 35, TX GPIO 32 |
| Реле тёплого пола | GPIO 2 (высокий уровень = включено) |
| Ethernet LAN8720 | PHY-адрес 0, MDC GPIO 23, MDIO GPIO 18, клок GPIO 17 |
| Питание | По документации Kincony; общий GND для внешних цепей |

Реле `RELAY_UNKNOW` (GPIO 15) определено в коде, но сейчас не используется. Ethernet-константы заданы, однако текущая прошивка вызывает инициализацию сети с `hasEth = false`, то есть работает по Wi-Fi; для проводной сети потребуется изменение кода.

## Установка и прошивка

Нужен [PlatformIO](https://platformio.org/) (PlatformIO Core 6 или новее) и доступ к плате по USB.

`ed-common` подтягивается из git и закреплена на теге `0.3.1` — так же, как остальные ed-* библиотеки в `lib_deps`. Дополнительно клонировать ничего не нужно.

```bash
# прошивка
pio run -e kc868a2 -t upload

# веб-интерфейс в LittleFS — обязателен, иначе страница не откроется
pio run -e kc868a2 -t uploadfs

# монитор порта
pio device monitor -e kc868a2
```

Скорость последовательного порта — **115200 8N1**. После включения прошивка специально ждёт 10 секунд перед инициализацией — это нормальное поведение.

Для OTA есть окружение `kc868a2_ota`:

```bash
pio run -e kc868a2_ota -t upload
```

Адрес контроллера и пароль OTA окружение берёт из файла `.env` в корне проекта (скопируйте `.env.example` в `.env`; файл игнорируется git). Пароль на стороне устройства задан в `src/main.cpp` и должен совпадать с `NEWTON_OTA_AUTH`; не публикуйте `.env`.

### Миграция с предыдущей прошивки

При обновлении с конфигурацией версии 1 файл `/config.bin` автоматически переходит на версию 2 при загрузке: Wi-Fi, MQTT и Modbus-настройки сохраняются, а единый префикс MQTT выводится из старой темы состояния (без суффикса `/state`; иначе берётся `newton/<chipid>`). Состояние автоматики освещения переносится в новый файл `/light_state.bin`, уставка и режим тёплого пола сохраняются. Повреждённый или отсутствующий старый конфиг заменяется настройками по умолчанию. После обновления удалите в Home Assistant устаревшую сущность ночного режима `light_night_mode_newton_<chipid>` — её заменила `light_automation_newton_<chipid>`.

## Первый запуск

1. Включите плату. Через ~10 секунд она поднимет точку доступа **`Newton_<MAC>`**. Пароль по умолчанию не задан.
2. Подключитесь к этой сети и откройте **http://192.168.4.1**.
3. На вкладке Network укажите SSID и пароль домашней Wi-Fi-сети и сохраните. Устройство применит настройки и попробует подключиться как клиент.
4. Если сеть недоступна, ed-network через серию неудачных проверок поднимает резервную точку доступа с тем же именем; детали поведения зависят от библиотеки.
5. Снова откройте веб-интерфейс и заполните MQTT: хост, порт (по умолчанию 1883), логин, пароль, префикс Home Assistant (`homeassistant`) и **MQTT topic prefix** — единый префикс тем (по умолчанию `newton/<chipid>`, максимум 46 символов; более длинные значения отклоняются в интерфейсе).
6. Проверьте настройки Modbus: скорость (по умолчанию 9600) и адреса устройств. Скорость применяется сразу, адреса — после перезагрузки.

## Веб-интерфейс

Одностраничное приложение (Preact + TypeScript + Vite) собирается из исходников в `frontend/` прямо в `data/`, которую PlatformIO заливает в LittleFS. Готовая сборка уже лежит в репозитории; пересобирать нужно только после изменения `frontend/`.

```bash
cd frontend
npm install          # один раз (Node 26 / npm 11)
npm run build        # typecheck + vite build -> ../data
pio run -e kc868a2 -t uploadfs
```

Сборка полностью заменяет содержимое `data/` (`emptyOutDir: true`). Для разработки запустите `npm run dev` и укажите устройство в `frontend/.env` (скопируйте `frontend/.env.example`, `VITE_DEV_API_TARGET=http://<device-ip>`): dev-сервер проксирует `/api/*` и `/healthcheck/*` на устройство.

Вкладки:

- **Status** — Wi-Fi, свободная память, uptime, причина сброса; готовность сервисов (MQTT, тёплый пол); перезагрузка.
- **Sensors** — актуальные значения датчиков (только чтение) и температура тёплого пола.
- **Control** — управление: тёплый пол (режим off/heat и уставка 16–40 °C), основной свет (вкл/выкл, яркость, цветовая температура), подсветка (вкл/выкл, яркость, цветовая температура, RGB-цвет) и ночной режим.
- **Modbus** — скорость шины и адреса устройств.
- **MQTT** — хост, порт, логин, пароль, префикс discovery и префикс тем.
- **Network** — Wi-Fi/AP-настройки (через ed-network).
- **Backup** — резервная копия и восстановление конфигурации.

Устаревшие эндпоинты `GET /api/settings` и `POST /api/settings/wifi` заменены на `GET /api/settings/mqtt` и `/api/network/*`; старый интерфейс удалён.

После изменения света значения в Control подтягиваются из снапшота устройства в течение ~0,5–1 с (очередь команд + следующий тик кэша); состояние ночного режима отражается через MQTT-эхо и может прийти с небольшой задержкой.

## Домашняя автоматизация

- Свет включается сам, когда в комнате есть человек и долго темно; выключается, когда человек ушёл.
- Любое ручное действие (кнопка, HA, MQTT) временно отменяет автоматику, чтобы она не спорила с человеком.
- Ночью при включении света основной свет горит красным на минимальной яркости (~2 %, 2700 K), чтобы не слепить.
- Тёплый пол поддерживает заданную температуру с запасом ±1 °C и не греет при неисправном датчике.
- Климат и присутствие просто транслируются в MQTT/Home Assistant.

## Home Assistant

При включённом auto discovery (по умолчанию) Newton сам публикует конфигурацию в `homeassistant/...`. В HA появятся:

- `light` — основной свет (яркость, цветовая температура 2700–6000 K);
- `light` — подсветка (яркость, RGB), новая сущность `backlight_newton_<chipid>`;
- `switch` — ночной режим автоматики освещения (`light_automation_newton_<chipid>`);
- `climate` — тёплый пол (режимы off/heat, текущая температура, уставка);
- сенсоры температуры, влажности, качества воздуха, CO₂ и освещённости;
- бинарный сенсор присутствия.

Уникальные идентификаторы сущностей содержат chipid устройства. Сенсоры, основной свет и присутствие сохраняют прежние идентификаторы. Если несколько контроллеров публикуют в один брокер, проверьте, что префиксы тем и discovery не пересекаются.

После обновления удалите устаревшую сущность ночного режима `light_night_mode_newton_<chipid>`: её заменила `light_automation_newton_<chipid>`.

## Ручное управление по MQTT

Все темы строятся от единого префикса (`mqttTopicPrefix`, по умолчанию `newton/<chipid>`). Ниже `<prefix>` — этот префикс.

| Назначение | Тема состояния | Тема команд | Payload и retain |
|---|---|---|---|
| Датчики климата и освещённости | `<prefix>/temperature/state`, `.../humidity/state`, `.../air_quality/state`, `.../co2/state`, `.../light_level/state` | — | число, retain, heartbeat раз в 60 с |
| Присутствие | `<prefix>/human_detected_1/state` | — | `"true"`/`"false"`, retain, heartbeat раз в 60 с |
| Основной свет | `<prefix>/light/state` | `<prefix>/light/set` | JSON; без retain |
| Подсветка | `<prefix>/backlight/state` | `<prefix>/backlight/set` | JSON; без retain |
| Ночной режим | `<prefix>/light_automation/state` | `<prefix>/light_automation/set` | `"true"`/`"false"`, без retain |
| Тёплый пол | `<prefix>/warm_floor/state` | `<prefix>/warm_floor/set` | JSON; без retain |

Состояние света — JSON с полями `enabled` (`"on"`/`"off"`), `brightness` (0–100), `tempColor` (Кельвины) и `color` (`"r,g,b"`); набор полей зависит от возможностей светильника. Команды света: просто `on`/`off` либо JSON с любыми из полей `brightness`, `tempColor`, `color`:

```json
{"brightness": 80}
{"tempColor": 3000}
{"color": "0,0,255"}
```

Тёплый пол публикует только четыре ключа:

```json
{
  "warmFloorCurrentTemperature": 27.5,
  "warmFloorMode": "heat",
  "warmFloorSetPoint": 28.0,
  "warmFloorState": "heating"
}
```

Команды тёплого пола отправляются в `<prefix>/warm_floor/set` одним JSON-объектом; можно передавать одно или несколько полей:

```json
{"warmFloorMode": "heat"}
{"warmFloorSetPoint": 27.5}
```

`warmFloorMode` — `"off"` или `"heat"`; `warmFloorSetPoint` ограничивается диапазоном 16–40. Ночной режим включается/выключается payload `"true"`/`"false"` в `<prefix>/light_automation/set`.

## Устранение неполадок

- **Нет данных с датчика.** Проверьте адрес Modbus, скорость и полярность A/B. При отказе датчика тёплого пола (более 20 ошибок подряд) реле принудительно выключается, а healthcheck сообщает об ошибке; климат и присутствие просто перестают обновляться.
- **Неверные адреса RS-485.** Исправьте их в веб-интерфейсе и перезагрузите устройство: адреса считываются при старте. Скорость меняется на лету.
- **Не открывается веб-интерфейс.** Убедитесь, что выполнена команда `pio run -e kc868a2 -t uploadfs`; статические файлы лежат в LittleFS.
- **Устройство не подключается к Wi-Fi.** Подождите резервную точку доступа `Newton_<MAC>` и проверьте SSID/пароль. Помните про 10-секундную задержку после включения.
- **Нужна перезагрузка.** Кнопка сохранения настроек в UI перезагружает плату; также можно отправить `POST /api/reboot`.
- **Диагностика.** Смотрите лог в `pio device monitor -e kc868a2` (115200) или `GET /api/status` (Wi-Fi, свободная память, uptime, причина сброса).

## Безопасность

Устройство не предназначено для выхода в интернет:

- веб-интерфейс и API работают без пароля и без HTTPS;
- `GET /api/settings/mqtt` возвращает MQTT-пароль открытым текстом; Wi-Fi-пароли через API не выдаются (вкладка Network отдаёт только флаги `hasWifiPassword`);
- OTA-пароль жёстко задан в прошивке (`src/main.cpp`), а для загрузки берётся из локального `.env`; в репозитории его нет.

Используйте только доверенную локальную сеть и не публикуйте порт 80 наружу. Считайте, что любой, кто видит устройство в сети, может прочитать его настройки.

## Ограничения

- Яркость света и автоматики — 0–100, как в Home Assistant.
- Вкладка Control управляет тёплым полом, основным светом, подсветкой и ночным режимом напрямую через API устройства; значения подтягиваются в течение ~1 с, а отображение ночного режима зависит от MQTT-эха.
- Ethernet LAN8720 в текущей сборке не включён.
- Известные ошибки и нюансы разработки перечислены в `AGENTS.md`.
